# МГТС Пульс стажировки

Go-монолит для сбора и просмотра обратной связи за шесть месяцев стажировки. Встроенный фронтенд, SQLite, роли HR / наставник / стажер, импорт Excel, webhook Tally, журнал действий HR и Python-агент для скрытых сигналов и планов 1:1.

## Быстрый запуск на Windows

Распакуйте ZIP и запустите `start-demo.cmd`. Готовый Windows x64 executable находится в `bin/`. Go и Python для этого способа не нужны. Откройте http://127.0.0.1:8080.

| Доступ | Логин | Пароль |
|---|---|---|
| HR | `hr` | `Mgts-demo-2026!` |
| Наставники Н-001…Н-005 | `mentor1`…`mentor5` | `Mgts-demo-2026!` |
| Стажеры СТ-001…СТ-005 | `intern1`…`intern5` | `Mgts-demo-2026!` |

Демонстрационные пароли предназначены для локального запуска. Исходные XLSX/DOCX в архив не включены. `data/history.json` содержит 60 нормализованных ответов из предоставленных таблиц; файл исключен из Git.

## Запуск из исходников

Требуется Go 1.25+; Node.js и npm не нужны.

```sh
go mod download
go run ./cmd/server -command demo
go run ./cmd/server
```

`demo` создает схему, демонстрационные учетные записи на пустой базе и импортирует историю. Повторный запуск не добавляет ответы и не сбрасывает существующие пароли. База — `data/pulse.db`; завершение — Ctrl+C.

Кабинеты: `/hr`, `/mentor`, `/intern`. Роль определяется серверной сессией, а не адресом страницы. Наставник видит назначенных ему стажеров, стажер — только свою историю, оценки, комментарии и опубликованные сообщения наставника.

## Docker

```sh
docker compose build
docker compose run --rm app -command demo
docker compose up -d app
```

Данные сохраняются в volume `pulse-data`. Остановка: `docker compose down` без удаления volume. Compose читает `.env`, если он создан из `.env.example`.

## Импорт исходных Excel

На новой базе сначала выполните `migrate`. Имена столбцов соответствуют анкетам, порядок столбцов произвольный.

```sh
go run ./cmd/server -command migrate
go run ./cmd/server -command import -intern "C:/path/ответы стажеров.xlsx" -mentor "C:/path/оценки наставников.xlsx"
```

Импорт атомарный. Первый импорт — 60 ответов, повторный — 0 новых. Пропуск сохраняется как `null`. Оценки вне 1–5, неверный период, подразделение или наставник отклоняются. Сочетание программы, стажера, месяца и источника уникально. Одинаковый `eventId` с теми же ответами идемпотентен; измененный повтор и второй ответ в тот же слот — `409`.

Новые участники регистрируются в кабинете HR → «Новый участник». Это позволяет принимать новые тестовые ответы, не меняя 60 исторических записей.

## Создание учетных записей

После `migrate` создайте HR и учетные записи участников. Пароль передается через окружение, минимум 12 символов.

```powershell
$env:USER_PASSWORD = 'replace-with-a-long-password'
go run ./cmd/server -command user -username admin -role hr
go run ./cmd/server -command user -username trainee6 -role intern -subject 'СТ-006'
go run ./cmd/server -command user -username mentor6 -role mentor -subject 'Н-006'
Remove-Item Env:USER_PASSWORD
```

Участник СТ-006 и его наставник должны быть зарегистрированы HR до создания этих двух учетных записей. `ADDR`, `DB_PATH`, секреты и URL задаются переменными окружения; обычный `go run` сам `.env` не читает. Параметр `-db` переопределяет путь базы для любой команды.

## Python-агент

Go вызывает `POST {AGENT_URL}/v1/analyze`, передает историю, `requestId`, `revision`, Bearer-токен и `Idempotency-Key`. Контракт: [docs/AGENT.md](docs/AGENT.md), схема API: [docs/openapi.json](docs/openapi.json).

```sh
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
pip install -r agent/requirements.txt
```

В терминале Python:

```powershell
$env:AGENT_TOKEN = 'replace-with-a-shared-secret-at-least-24-chars'
python -m uvicorn app:app --app-dir agent --host 127.0.0.1 --port 8000
```

В терминале Go до запуска сервера:

```powershell
$env:AGENT_URL = 'http://127.0.0.1:8000'
$env:AGENT_TOKEN = 'replace-with-a-shared-secret-at-least-24-chars'
go run ./cmd/server
```

Для живой модели задайте Python-процессу `AGENT_LLM_URL` (полный URL совместимого с Chat Completions эндпоинта с поддержкой JSON), `AGENT_LLM_MODEL` и, если провайдер требует авторизацию, `AGENT_LLM_TOKEN`. Используйте сервис, одобренный для обработки комментариев анкет. Без провайдера агент использует ранее проверенную разметку, если она доступна, и формирует планы по шаблону. Для изолированной проверки связи предусмотрен `AGENT_REFERENCE_MODE=1`. В Compose задайте параметры модели в `.env`, используйте `AGENT_URL=http://agent:8000` и `docker compose --profile ai up --build -d` после первоначального `demo`.

Для автономного показа скрытых сигналов укажите `AGENT_REVIEWED_LABELS` как путь к локальному файлу с проверенной разметкой. Формат описан в [контракте агента](docs/AGENT.md). Приложение сверяет хэш и дословный фрагмент с текущим ответом. Файл `data/reviewed-labels.json` исключен из Git. Если подходящей разметки нет, обзор продолжает показывать числовые сигналы.

Для проверки исторического примера войдите как HR, откройте СТ-004 и запросите анализ месяца 3. После обработки проверьте основания скрытых сигналов и план 1:1. При смене на месяц 4 остается числовой сигнал о нагрузке 2/5. Для СТ-005 в месяце 1 шаблон предлагает короткие еженедельные встречи. Новая анкета ставит анализ в очередь автоматически.

Ответ анкеты сохраняется до обращения к AI. Очередь переживает перезапуск, делает до четырех попыток; ошибки и повторный запуск видны HR → «Интеграции». Выводы другой ревизии не показываются, ссылки на несуществующие или измененные оценки/комментарии отклоняются.

## Рекомендации и HR-задачи

Рекомендации по результатам анкет отображаются в кабинетах HR и наставника. После подтверждения HR их можно превратить в задачи во внешней системе через HTTP-адаптер. [Настройка, роли и контракт](docs/HR_TASKS.md).

## Внешние формы

Поддержаны Tally с HMAC-подписью и нормализованный Bearer-webhook. Настройка двух форм, поля и локальный тест: [docs/INTEGRATIONS.md](docs/INTEGRATIONS.md).

Адаптер реализован и проверен на подписанных запросах. Живые формы не созданы: для этого нужны аккаунт Tally и публичный HTTPS endpoint. Статус «настроено» в UI означает наличие конфигурации, а не подтвержденную доставку из Tally.

## Проверка

```sh
go test ./... -count=1
go vet ./...
go build ./cmd/server
pip install pytest httpx
python -m pytest agent
```

Проверяются импорт и пропуски, 2/5 и 4/5 по нагрузке СТ-004 в месяцах 4 и 5, конфликты и параллельные повторы, доступ по ролям, CSRF, сессии, публикация обратной связи, новый участник, подпись Tally, очередь и evidence агента. Фактические результаты: [docs/VALIDATION.md](docs/VALIDATION.md).

## Структура и ограничения

`cmd/server` — запуск и CLI; `internal/pulse` — API, SQLite, импорт, правила и очередь; `web` — встроенный HTML/CSS/JS; `agent` — FastAPI-контракт; `docs` — API, интеграции, методика и сценарий защиты.

Светофор опирается на числовые правила и добавляет подтвержденные скрытые сигналы за выбранный месяц. Скрытый сигнал связывает негативный комментарий с оценкой 4–5 по той же теме в той же анкете. В карточке HR доступен черновик плана 1:1 на основе подтвержденных данных месяца. Это основания для проверки человеком.

Прототип рассчитан на одну программу и один процесс Go. Для внедрения нужны корпоративный SSO, HTTPS с `COOKIE_SECURE=true`, согласованный сервис форм/модели, правила доступа и хранения данных, резервное копирование SQLite и проверка качества сигналов на размеченных примерах. План пилота и измеримые показатели: [docs/METHOD.md](docs/METHOD.md).
