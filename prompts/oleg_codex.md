# Олег — backend и внешняя интеграция, Codex

Ты владелец задач B01 и B02 для финала МГТС «Код города». Срок команды — около 2,5 часа на момент постановки. Репозиторий был пустым; не предполагай существующий код. Изучи `AGENTS.md`, `PRODUCT.md`, `ARCHITECTURE.md`, `CONTRACTS.md`, `ACCEPTANCE.md`, ТЗ и обе анкеты рядом с репозиторием. Общая цель: HR получает новый ответ из внешней формы, видит историю, приоритет и первичные данные. Резван отвечает за UI, Егор за `analysis/`, Маша за защиту. Работай в ветке `oleg/api-integration`, владеешь `backend/` и `README.md`. Не меняй `analysis/` и `frontend/`; изменения общего JSON-контракта сначала согласуй с координатором.

P0 B01: сделай запускаемый FastAPI/SQLite сервис либо согласуй равноценный минимальный стек до реализации. Импортируй оба предоставленных Excel из локального пути без публикации этих файлов в Git. 30+30 ответов должны связываться по `program_id`, ID стажера и месяцу; проверяй 1–5, обязательные поля, принадлежность периода и подразделение. Храни исходные ответы отдельно от вычисленных сигналов. Импорт и `POST /api/v1/responses` идемпотентны по event ID; измененный повтор — 409. API обзор/профиль/интеграции реализуй по `CONTRACTS.md`. Не придумывай пропущенные оценки. Сделай единый адаптер к чистой функции Егора через оговоренный интерфейс, а пока его нет — отдай реальные ответы и пустой список сигналов без ложной аналитики. Запиши команду запуска, импорта и тестов в README.

P0 B02: выбери внешний сервис, в котором команда может за время финала создать две формы. Сразу сообщи координатору выбранный сервис, требования к аккаунту и публичному URL. Настрой реальный webhook или опрос API. Нужны маппинг полей двух форм, секрет в env, логирование, наблюдаемый статус доставки, повторная доставка и тестовый ответ. Endpoint сам по себе не является готовой интеграцией: отметь DONE только после отправки из формы и появления данных в API. Если доступ к аккаунту или публичному URL блокирует путь, быстро сообщи конкретный блокер и продолжай B01. Не публикуй секреты, реальные ответы и персональные данные.

Приемка: 60 исторических ответов после первого импорта, столько же после второго; 5 ID × 6 месяцев; профиль СТ-004 показывает 2/5 по нагрузке в месяце 4 и 4/5 в месяце 5; нет нулей вместо пропусков; новый тестовый ответ появляется автоматически; дубликат не создает запись; API возвращает evidence в схеме контракта после подключения модуля Егора. Напиши необходимые тесты валидатора, импорта и webhook. Работай малыми коммитами без force push.

Передача: ID, DONE/IN PROGRESS/BLOCKED, файлы, ветка и SHA, команды и результаты тестов, URL/статус форм (без секретов), изменения контракта, ограничение и следующий шаг для интеграции. Если времени мало, сначала B01 с работающим импортом/API, затем минимальный B02; не трать время на P2.
