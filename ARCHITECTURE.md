# Архитектурная граница

Репозиторий стартовал пустым. Предлагаемый минимальный стек: Python/FastAPI + SQLite для API и хранения, React/Vite для интерфейса, отдельный чистый модуль `analysis/` для детерминированных сигналов. Выбор окончателен после проверки доступных навыков и окружения Олегом; смена стека требует сохранения `CONTRACTS.md`.

Поток: внешний сервис анкет → webhook/poll adapter → проверка секрета и схемы → исходный ответ в БД → нормализованные поля → пересчет сигналов → API → UI. Исторический Excel импортируется тем же валидатором, с `source_event_id`, созданным из источника/ID/периода. Повторная доставка не создает вторую запись. Исправления ответа сохраняют версию или явно отклоняются; молчаливое перезаписывание запрещено.

Таблицы: `responses` (ID события, источник, ID стажера, ID наставника, подразделение, период, сырой JSON, время получения, версия), `scores` (response ID, показатель, 1–5), `comments` (response ID, поле, текст), `signals` (расчетная версия, стажер, период, тип, статус, evidence JSON). Отсутствующий ответ хранится как отсутствие записи. Внешний сервис и способ публичной доставки надо подтвердить действующим тестом; endpoint без подключенной формы не считается интеграцией.

LLM опциональна: только интерпретация текста со структурированным результатом и ссылкой на исходную цитату. При недоступности LLM числовые правила и весь UI продолжают работать. Эвристические текстовые темы не должны превращаться в утверждения о состоянии человека.

Границы владения: Олег — `backend/`, `frontend/`, внешний адаптер; Егор — `analysis/` и тесты правил; Резван — дизайн в Figma, ассеты и согласование UI, помощь AI; Маша — сценарий ценности и защита. Координатор — контракты, проверка интеграции и приемка. Реальное распределение см. `TASKS.md`.
