## Что не проверено и не заявляется готовым

- Живая отправка из опубликованных Tally-форм: нет предоставленного аккаунта и публичного HTTPS endpoint. Реализован и проверен адаптер, настройка описана в INTEGRATIONS.md.
- Качество AI-модели: Qwen подключен и проверен на исторических ответах, но независимой оценки точности и полноты смысловых выводов нет. Проверены JSON, доказательства, сохранение и повторы; семантическую правильность должен проверять HR.
- Docker image build/run: Docker CLI установлен, но Docker Engine в среде не запущен. Проверена только конфигурация Compose; нативный запуск и сборка Go проверены.
- Нагрузочные испытания, Linux-контейнер, корпоративный SSO, резервное восстановление и производственная эксплуатация не проверялись. SQLite/очередь рассчитаны на один процесс.

Пакет содержит исходники и нормализованную историю, а не действующую базу с сессиями и паролями. Демонстрационные учетные записи создаются только явной командой demo.


## Обновление с AI и автоматической регистрацией

- `/v1/models` предоставленного прокси принял ключ; реальный `POST /v1/chat/completions` с моделью `qwen/qwen3.6-flash` дал HTTP 200.
- Реальный анализ 12 ответов СТ-004 через Python завершился за 8,4 секунды. Через работающий FastAPI скрипт test_live_agent.py проверил модельный ответ и идентичный повтор; все evidence сверены с историей.
- Полная цепочка Go → FastAPI → Qwen сохранила анализ в SQLite. Один ответ генерации не прошел строгую проверку, не был опубликован; следующая попытка завершилась done.
- Защищенные формы автоматически создали СТ-DEMO и привязали Н-DEMO. Повторы сохранили ровно две анкеты. Ручной HR endpoint регистрации удален.
- Go-тесты дополнительно проверяют оба порядка прихода анкет, атомарный откат регистрации, запрет незаметной смены наставника и отсутствие автоматической регистрации в обычном импорте.
- Ключ провайдера использован только в окружении проверочного Python-процесса. Он не сохранен в исходниках, истории или ZIP.

- Обновленный браузерный тест подтвердил: кнопки «Новый участник» нет, старая HR-ручка дает 404; подписанные формы создали карточку без ручного добавления, карточка появилась через автообновление, новый участник доступен в действиях HR; JavaScript-ошибок нет.

## Docker и публичная ссылка ngrok

Добавлен ngrok с NGROK_AUTHTOKEN из .env, локальной панелью 127.0.0.1:4040 и отключенным сохранением тел запросов. Plain docker compose up --build -d поднимает agent, app и ngrok без дополнительных profiles. Агент ожидается по healthcheck, туннель — после готовности приложения.

Docker entrypoint на новом volume выполняет demo, на существующей базе — migrate без повторного импорта. Явные CLI-аргументы передаются Go напрямую. Основной Go-код, Python-агент, фронтенд и исполняемый файл не изменялись.

docker compose config --format json прошел: проверены три сервиса по умолчанию, порядок health-зависимостей, переменная ngrok-токена, отсутствие внешнего Python-порта и привязка панели 4040 к loopback. PowerShell-блоки README синтаксически проверены. Docker Engine в среде недоступен, поэтому build/run контейнеров и реальный туннель ngrok не проверены. Пользователь должен заполнить свой NGROK_AUTHTOKEN.
