## A. Запуск

Python 3.9+ и openpyxl. HTTP-клиент входит в стандартную библиотеку. Исходные Excel читаются локально. API-режим выполняет GET, пока явно не передан параметр --ingest-program-id.

~~~powershell
$env:BASE_URL = 'http://127.0.0.1:8000'
$src = 'D:\ML\МГТС'
$qa = @(
    'qa/smoke.py'
    '--intern-xlsx', (Join-Path $src 'ответы стажеров.xlsx')
    '--mentor-xlsx', (Join-Path $src 'оценки наставников.xlsx')
    '--program-id', 'demo-2026'
)
python @qa --excel-only
python @qa
# На стенде задайте QA_INGEST_TOKEN, если адаптер принимает Bearer-токен.
# Подставьте свежую тестовую программу со стажёром СТ-999 и пустым месяцем 1.
python @qa --ingest-program-id qa-smoke-run-01
~~~

Коды выхода: 0 — выполненные проверки прошли, 1 — есть FAIL, 2 — запрошенная проверка недоступна. Для проверки повторного импорта Олег запускает штатный импорт тех же файлов второй раз, затем QA повторяет A с тем же program_id.

CONTRACTS.md задаёт маршруты и поля сущностей. Временные допущения smoke о внешнем JSON: overview содержит period, participants, responses.{intern,mentor}.{expected,received} и queue с intern_id/status, профиль содержит status, history (строки period с intern/mentor, отсутствующий ответ — null) и signals, POST возвращает id и duplicate. Олегу нужно дать фактические примеры ответов, способ авторизации и порядок подготовки тестовой программы. Если схема отличается, адаптировать smoke по подтверждённым ответам.

## B. Доставка из внешних форм

1. Открыть UI чистой тестовой программы. Использовать синтетический ID, согласованный месяц 1–6 и тестового наставника. Снять срез профиля до отправки.
2. Отправить по одному синтетическому ответу через обе внешние формы. Использовать различимые комментарии и оценки, для которых ожидаются сигналы. Олег сверяет ID доставки и результат в GET /api/v1/integrations. QA сверяет ID, период, источник и оценку в GET /api/v1/interns/{intern_id}.
3. Проверить источники и evidence новых сигналов на API, затем те же оценки и сигналы в открытом HR-профиле. Зафиксировать время, ID доставки и наблюдение в UI для каждой формы. Повторить доставку одного события и сверить отсутствие дубля в истории. Если провайдер позволяет безопасно воспроизвести ошибку доставки, проверить видимость ошибки и повтор доставки.
