# Временный QA-стенд

Caddy принимает запросы Cloudflare Quick Tunnel на 127.0.0.1:18765. GET /healthz возвращает состояние входа. В начальной конфигурации остальные маршруты возвращают 404. Локальные API и UI запускаются из веток владельцев, исторические Excel используются локально.

## Запуск на Windows

Установить Caddy и cloudflared. Из корня репозитория запустить команды в двух терминалах. Можно использовать полные пути к исполняемым файлам.

~~~powershell
$env:QA_WEBHOOK_PATHS = '/__qa_webhook_disabled__'
caddy run --config qa/Caddyfile --adapter caddyfile
~~~

~~~powershell
cloudflared tunnel --no-autoupdate --protocol http2 --url http://127.0.0.1:18765 --http-host-header 127.0.0.1:18765
~~~

Взять HTTPS-адрес из вывода cloudflared и проверить GET /healthz. Ответ 200 с qa-ingress подтверждает доступность входа. Адрес меняется после перезапуска туннеля. Для остановки завершить оба процесса.

## Подключение приложения

1. Запустить backend на 127.0.0.1:8000 штатной командой из ветки Олега. Запустить UI из ветки Резвана и направить его на этот API. Запуск smoke описан в [STATUS.md](STATUS.md).
2. С Олегом подтвердить фактические пути внешних webhook, проверку подписи провайдера и отдельную синтетическую программу. Задать пути целиком, без шаблонов, разделяя пробелом. После reload текущий адрес туннеля сохраняется. Пример ниже использует условные пути.

~~~powershell
$env:QA_WEBHOOK_PATHS = '/webhooks/intern /webhooks/mentor'
caddy reload --config qa/Caddyfile --adapter caddyfile --address 127.0.0.1:20191
~~~

3. В настройках форм указать HTTPS-адрес туннеля и соответствующие webhook-маршруты. Выполнить сценарий B из [STATUS.md](STATUS.md). История и внутренний POST /api/v1/responses доступны команде локально. Если выбран polling, шаги с webhook пропустить и проверить фактическую автосинхронизацию.
