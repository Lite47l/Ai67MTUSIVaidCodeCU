# Контракт Go и Python

Версия `1.0`. Go является владельцем ответов, прав доступа и истории. Python получает историю одного стажера и возвращает только производный анализ. Нельзя менять исходные ответы, выдавать инструкции из комментариев за системный промпт или передавать модели секреты.

## Запрос

`POST /v1/analyze`, JSON, `Authorization: Bearer <AGENT_TOKEN>`, `Idempotency-Key: <requestId>`.

```json
{
  "schemaVersion": "1.0",
  "requestId": "analysis:<64 hex characters>",
  "revision": "<64 hex characters>",
  "programId": "mgts-internship",
  "internId": "СТ-004",
  "history": [
    {
      "eventId": "history:intern:СТ-004:4",
      "programId": "mgts-internship",
      "internId": "СТ-004",
      "department": "HR-блок",
      "month": 4,
      "source": "intern",
      "scores": {"taskClarity": 5, "mentorSupport": 5, "workload": 2, "interest": 5, "development": 5, "teamwork": 5, "satisfaction": 4},
      "comments": {
        "difficulties": "Нагрузка была слишком высокой из-за нескольких проектов одновременно.",
        "barriers": "Основная сложность — высокая нагрузка; по задачам и взаимодействию проблем нет."
      },
      "receivedAt": "2026-11-26T00:00:00Z"
    }
  ]
}
```

Пример сокращен до одной записи, время иллюстративное. В реальном запросе до 12 записей, отсортированных по месяцу и источнику. `mentorId` есть только у ответов наставника. `raw` не передается. `revision` — SHA-256 списка канонических хешей ответов, вычисляет Go; Python возвращает значение без пересчета.

## Ответ

HTTP 200:

```json
{
  "schemaVersion": "1.0",
  "requestId": "analysis:<64 hex characters>",
  "revision": "<same revision>",
  "summary": "В месяце 4 отмечена высокая нагрузка. Нужно проверить ее распределение.",
  "signals": [{
    "id": "workload-m4",
    "kind": "workload",
    "severity": "critical",
    "title": "Низкая комфортность нагрузки в месяце 4",
    "evidence": [{"eventId": "history:intern:СТ-004:4", "field": "workload", "value": "2"}]
  }],
  "recommendations": ["Обсудить распределение параллельных задач со стажером и наставником."]
}
```

Учитывайте всю историю: нагрузка СТ-004 восстановилась в месяце 5. Исторический сигнал не означает текущую проблему; резюме должно различать их. `severity` — `positive`, `attention`, `critical`. `signals` и `recommendations` обязательны, даже если пусты. Каждый сигнал имеет минимум одно доказательство. Для оценки `value` — строка числа; для комментария — полный исходный текст, без пересказа или обрезания. Поле — ключ из `scores` или `comments`. Поля, источники и периоды берутся из указанного `eventId`.

Go проверяет версию, идентификаторы запроса и ревизии, размеры ответа, наличие массивов, уникальность ID сигналов, уровни важности и точное совпадение evidence с историей. Это проверка происхождения доказательств, не доказательство семантической правильности вывода модели.

## Отказ и повтор

Таймаут одного вызова — 25 секунд. Четыре попытки, задержки 2/4/8 секунд перед следующими попытками; после четвертого отказа `failed`. HR может повторить запрос. Не возвращайте HTTP 200 при ошибке модели. Ограничение ответа — 1 MiB.

Повтор с тем же requestId и тем же содержимым возвращает прежний результат; измененный повтор — 409. В адаптере Python кеш ограничен 128 результатами в памяти, поэтому после перезапуска вычисление может повториться. При масштабировании сохраните результаты в постоянном хранилище. HTTP-вызов модели ограничен 20 секундами внутри 25-секундного таймаута Go. Не используйте внешний побочный эффект внутри анализа.

Очередь Go сохраняется в SQLite. При старте `running` возвращаются в очередь, актуальные истории сверяются с заданиями. Старое задание до вызова помечается `superseded`; старый ответ после изменения истории не показывается пользователю. Поддержан один процесс Go; горизонтальное масштабирование требует атомарного захвата задания и lease.

`/docs` Python-сервиса содержит интерактивную спецификацию. JSON Schema: `agent-request.schema.json`, `agent-result.schema.json`. Автоматический тест реального HTTP-обмена и отбраковки ошибочного evidence находится в `internal/pulse/pulse_test.go`.


## Подключенная модель

Агент использует OpenAI-совместимый endpoint `POST /v1/chat/completions` прокси `https://llm-proxy.spirit.culab.ru`, модель `qwen/qwen3.6-flash`. Переменные Python-процесса: `LLM_BASE_URL`, `LLM_MODEL`, `LLM_API_KEY`. `AGENT_TOKEN` — отдельный секрет Go ↔ FastAPI, его нельзя заменять ключом провайдера. Ключ провайдера не передается в Go, UI, промпт или файлы истории.

Промпт находится в `agent/llm.py`, формулировки анкет — в `agent/labels.json`. Внутренний ответ модели содержит `summary`, `signals`, `recommendations`. Модель выбирает `evidenceIds` из переданного каталога, Python разрешает их в точные eventId/field/value. Неизвестный ID, неверный JSON, обрезанная генерация или нарушение схемы дают 502; Go дополнительно проверяет все доказательства перед сохранением. Внешний контракт `/v1/analyze` не изменен.

Используются temperature=0.1, max_tokens=3500, JSON-object output, отключенное reasoning. Параметры reasoning соответствуют [формату OpenRouter](https://github.com/OpenRouterTeam/docs/blob/main/guides/best-practices/reasoning-tokens.mdx) и проверены на данном прокси. Содержимое reasoning не читается и не показывается. Это структурированный анализ истории без инструментов и внешних действий; свободное выполнение команд моделью не поддерживается.

Проверка ссылок доказывает происхождение цитат, но не семантическую правильность резюме. Возможны неверные обобщения модели; HR должен сверять вывод с оценками и комментариями. Промпт требует различать прошлые и текущие проблемы, не приписывать причины без данных и не выдавать кадровые/медицинские заключения.


## Скрытые сигналы и планы разговора

`conversationPlans` — необязательное расширение ответа агента, до одного плана на каждый из шести месяцев. Схема: month, situation, evidenceIds, questions (ровно 3), actionType, mentorMessage. Ссылки имеют вид eventId#field и обязаны существовать в том же месяце. mentorMessage принимается только при точном совпадении с нейтральным шаблоном соответствующего действия: модель не может вставить в него комментарий стажера.

`text_score_mismatch` формируется кодом после проверенной LLM-разметки: негативная тема не growth, связанная оценка ≥4 и точная цитата в том же ответе. Во внешнем evidence передаются исходная оценка и полный исходный комментарий; рабочая цитата проверяется как подстрока перед построением сигнала. Такой kind зарезервирован: основной генератор резюме не может выдать его самостоятельно.

Общий Qwen-анализ сохранен. Разметка и планы запрашиваются одним пакетным вызовом параллельно существующему резюме; каждый транспорт имеет 20-секундный таймаут, Go — прежний 25-секундный. При недоступности ветки обогащения она возвращает шаблоны и не подменяет основной анализ. После прогрева кеша возможен отдельный пакетный вызов только для планов. Нет ключа/связи — исходный светофор и числовой шаблон плана продолжают работать в Go.

Проверенная разметка кешируется по eventId, полю и SHA-256 текста с версией классификатора: native — work/agent-comment-labels.json, Compose — отдельный volume agent-cache. Неверная цитата не кешируется; измененный текст не получает старую разметку. Кеш содержит фрагменты комментариев и остается локальным.

Новые приватные данные выдаются только HR. Для наставника/стажера conversationPlans и hiddenSignals пусты, ai.conversationPlans удалено, скрытые сигналы не попадают в общий ai.signals. Прежняя политика доступа к исходным анкетам, опубликованной обратной связи и общему AI-резюме сохранена.

Явный повторный запрос HR создает новый ASCII requestId для done/failed, чтобы старый кеш Python не мешал обновлению. Pending/running не дублируются. Формы по-прежнему вызывают идемпотентную Queue и не запускают пересчет от простого повторного webhook.
