# Скрытые сигналы и план разговора

Из переданного ZIP перенесены только две фичи, соответствующие пунктам 1–2 killer-features.md. Дополнительная петля эффекта действий и диагностика программы не добавлялись. Прежний журнал действий HR сохранен.

## Скрытый сигнал

LLM размечает темы и тональность отдельных комментариев. Код проверяет дословную цитату и исключает рост, отрицания и явно описанное восстановление. После этого чистое правило сопоставляет негативную тему с оценкой того же ответа:

| Тема | Стажер | Наставник |
|---|---|---|
| feedback | mentorSupport | communication |
| clarity | taskClarity | taskUnderstanding |
| workload, planning | workload | deadlines |
| team | teamwork | communication |

Если оценка ≥4, формируется text_score_mismatch с severity=attention и двумя доказательствами: оценкой и полным исходным комментарием. Несколько комментариев одного ответа не теряются; одинаковая пара комментарий/показатель не дублируется. Рост не окрашивает лучших стажеров в проблему. Проверка цитат доказывает происхождение текста, а смысл разметки остается предметом оценки HR.

Сигнал влияет только на светофор HR в соответствующем месяце. Критичный числовой сигнал остается приоритетным. Новые скрытые сигналы не выводятся из ключевых слов без LLM-разметки. Проверенная разметка сохраняется локально и переиспользуется при неизменном хеше текста.

## План 1:1

По данным одного месяца формируются ситуация, основания eventId#field, три открытых вопроса, тип действия и черновик сообщения наставнику. Предложение модели принимается только при валидных ссылках, допустимом действии и трех разных вопросах. Иначе используется шаблон. Go дополнительно строит шаблон для низких оценок без доступного агента.

Сообщение наставнику всегда берется из нейтрального шаблона: исходные комментарии и модельный пересказ в него не попадают. План приватен для HR и не отправляется автоматически. Учетные записи, исходная история и публикации наставника работают по прежним правилам.

## Совместимость с нашим проектом

Qwen-резюме, переменные модели и ImportTrusted сохранены. Ручная регистрация HR добавлена рядом с автоматической; полный анализ доступен HR, а наставник получает нейтральные рекомендации по своей роли. Сохранены автозагрузка участников, webhook-подписи, идемпотентность, проверка ревизий/evidence, 60 исторических ответов, исходные оценки и обратная связь наставника.

Планы сохраняются в существующем JSON анализа. Для подтверждённых HR-задач при запуске добавляется таблица hr_task_deliveries; исходные анкеты не изменяются. Старые результаты без conversationPlans читаются. Для обогащения уже обработанной истории нажмите «Запросить анализ» в HR. Исходные анкеты и опубликованные сообщения при этом не меняются.

Обновление Docker: `docker compose up --build -d`. Не удаляйте volume pulse-data. Кеш разметки хранится отдельно в agent-cache. Прежний `.env` с вашим Qwen-токеном сохранен.

## Проверка

На реальном Qwen проверены шесть обязательных случаев из предложения: СТ-004 месяц 3 с двух сторон, СТ-001 месяцы 1–2, СТ-002 месяц 4 и наставник СТ-004 месяц 4. Контрольные запросы на рост и фразы с отрицанием не стали скрытыми сигналами. Для СТ-005 месяц 1 подтвержден weekly_1on1. Это проверка ограниченного набора примеров, не оценка точности модели на независимой выборке.

Автотесты дополнительно проверяют приватность планов, корректность месяца, неизвестные ссылки, опасный текст сообщения наставнику, обновление старого анализа, кеш и сохранение существующего резюме Qwen. Команды — в TESTING.md.
