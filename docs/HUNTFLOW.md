# Сохранение рекомендаций в Huntflow

В карточке стажёра HR может выбрать «Сохранить заметку в Huntflow». Действие добавляет нейтральную рекомендацию за выбранный месяц в блок личных заметок связанной карточки Huntflow. Интерфейс показывает состояние отправки и ссылку на карточку. Отправка задачи через `HR_TASK_URL` доступна отдельно.

В Huntflow передаются нейтральный заголовок, описание, номер месяца и техническая метка. Исходные ответы, оценки и доказательства остаются в «Пульсе стажировки». Сценарий использует существующую карточку. Время встречи, этап подбора и участники не меняются.

## Настройка

Понадобятся организация Huntflow, токен API с доступом к чтению и созданию заметок и соответствия между внутренними ID стажёров и карточками Huntflow. Используйте карточки из одной организации. ID организации можно узнать через `GET /v2/accounts`. Ссылку на карточку скопируйте из интерфейса Huntflow.

Задайте переменные окружения для Go. В Docker Compose их можно указать в локальном `.env`.

```dotenv
HUNTFLOW_API_URL=https://api.huntflow.ru
HUNTFLOW_ACCOUNT_ID=123
HUNTFLOW_ACCESS_TOKEN=<токен>
HUNTFLOW_APPLICANT_MAP='{"СТ-006":{"applicantId":456,"profileUrl":"https://huntflow.example.test/ссылка-на-карточку"}}'
```

Значения в примере иллюстративные. Для тестового контура укажите origin API из вашей [песочницы Huntflow](https://sandbox.huntflow.dev/). Путь `/v2` добавляет приложение. При ротации токена обновите `HUNTFLOW_ACCESS_TOKEN` и перезапустите Go.

## API и повторная проверка

Клиент вызывает `GET /v2/accounts/{account_id}/applicants/{applicant_id}/logs` с фильтром личных комментариев и `POST` на тот же маршрут с полем `comment`. Параметр `vacancy` опускается, чтобы запись попала в личные заметки. [Huntflow API v2](https://api.huntflow.ru/v2/docs).

Внутренний маршрут `POST /api/v1/hr/interns/{id}/recommendations/{recommendation}/huntflow?month=2` доступен только HR. При отсутствии привязки он возвращает 409. Профиль HR возвращает состояние в `recommendations[].huntflowDelivery` независимо от состояния обычной задачи.

После ошибки с неясным результатом приложение предлагает проверить запись. Повторная проверка ищет техническую метку в журнале кандидата. Если метка найдена, приложение показывает существующую заметку. Если результат POST остаётся неизвестным, приложение продолжает проверку журнала без повторного POST. Такой случай требует ручной сверки. При однозначном отказе, например HTTP 401, после устранения причины доступна повторная отправка.

После настройки проверьте сценарий на тестовой карточке. В кабинете HR откройте рекомендацию, нажмите «Сохранить заметку в Huntflow» и убедитесь, что ссылка открывает нужную карточку и в ней видна одна заметка.
