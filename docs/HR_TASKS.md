# Рекомендации и задачи для HR

В профиле HR и закреплённого наставника за выбранный месяц появляется массив `recommendations`. Стажёр получает опубликованную обратную связь наставника через существующее поле `feedback`. Решение о получателе рекомендации принимает Go.

| Действие | Получатель |
| --- | --- |
| `reduce_load`, `weekly_1on1`, `clarify_tasks` | Закреплённый наставник |
| `increase_task_complexity`, `hr_talk`, `other` | HR |

У наставника остаются оценки и нейтральные вопросы к разговору. Комментарии из анкеты стажёра и полный план агента доступны HR. Просьба о более сложной работе отображается у HR как запрос на развитие. На уровень риска она сама по себе не влияет. При отсутствии результата агента рекомендация может строиться по числовым сигналам и явной формулировке запроса на развитие.

## Подключение сервиса задач

В окружении Go задайте `HR_TASK_URL` и при необходимости `HR_TASK_TOKEN`. Для удалённого адреса нужен HTTPS. Локальный тестовый сервис может слушать HTTP на loopback. В Docker выполните `docker compose up --build -d`. Кнопка отправки появится у рекомендаций в профиле HR. SQLite обновляет схему при запуске. Рекомендации работают и без настроенного сервиса задач.

HR нажимает «Подтвердить и создать задачу». Приложение сохраняет подтверждение и вызывает заданный endpoint методом POST. Сервис получает заголовок `Idempotency-Key` со стабильным идентификатором. При заданном токене приложение добавляет `Authorization: Bearer …`.

```json
{
  "id": "stable-recommendation-id",
  "programId": "mgts-internship",
  "internId": "СТ-006",
  "month": 2,
  "actionType": "reduce_load",
  "assignee": "Н-006",
  "assigneeRole": "mentor",
  "description": "Провести короткий созвон про нагрузку. Сверить объем параллельных задач и сроки."
}
```

Для действия HR в `assignee` передаётся имя пользователя, подтвердившего задачу. Сервис возвращает HTTP 201 или 200 с `{"id":"TASK-42","url":"https://tasks.example.test/TASK-42"}`. Сервис или его адаптер должен возвращать ту же задачу при повторе с тем же ключом, включая случай, когда первая задача была создана, а ответ потерян. Фактический получатель и содержимое запроса сохраняются при первом подтверждении. Доставка со статусом `sent` повторно не отправляется.

## Проверка и API

- `GET /api/v1/hr/interns/{id}?month=2` возвращает рекомендации и состояние отправки.
- `GET /api/v1/mentor/interns/{id}?month=2` возвращает только рекомендации для назначенного наставника.
- `POST /api/v1/hr/interns/{id}/recommendations/{recommendation}/confirm?month=2` подтверждает задачу. Ответы 200, 202 и 502 соответствуют созданной задаче, выполняющейся отправке и ошибке доставки.

Тест `TestConfirmedHRTaskRetriesWithSameExternalKey` поднимает локальный принимающий сервис. Он имитирует потерю ответа после создания и проверяет, что повторное подтверждение возвращает ту же задачу.
